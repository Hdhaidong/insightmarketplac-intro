Capability Absorption · 能力吸收

三大体系，一次吸收

我们逐项拆解了当前最具代表性的三类 AI 员工产品——云端自动销售代理、多智能体编排框架、本地优先 AI 同事，把它们各自最强的能力面，收进同一个产品底座。

Source 01 · 记忆与增长

AutoManus 体系

云端 AI 业务员的核心是「AI 记忆引擎」：从对话捕获到跟进行动的完整闭环。

  • 沟通数据自动捕获每次对话自动沉淀，无需手工录入
  • 客户全景档案动态更新的结构化客户画像
  • 每日简报与战术预警讲清楚下一步该做什么
  • 上下文跟进内容生成基于历史沟通自动起草
Source 02 · 编排与护栏

MARCO 体系

多智能体实时编排框架的精髓：让多个 Agent 协同干活，且全程可控。

  • 多智能体任务编排复杂任务拆解、分派与协同
  • 护栏与输出校验行为约束、结果验证、错误恢复
  • 可视化工作流编辑拖拽式编排，低代码 / 零代码双模式
  • 多类节点资产LLM / 知识检索 / 代码执行 / 条件 / 循环 / HTTP
Source 03 · 本地与交付

OpenWorker 体系

本地优先 AI 同事的路线：交付成品，而不是只给聊天回复。

  • 本地设备操控读写文件、运行命令、处理本地项目
  • 真实成果交付文档 / 表格 / 报告 / 网页直接落盘
  • 连接器生态消息、日历、项目、邮箱等系统联动
  • 后台自动化与多角色协作定时任务、异步派发、分角色 Agent
Memory Engine · 记忆引擎闭环

捕获 → 记忆 → 洞察 → 行动

对标 AutoManus「单一记忆库 · 四层自主架构」，insightmarketplac 的数据主干是同一条价值链：每一次沟通都变成记忆，每一次记忆都喂给洞察，每一条洞察都落成可审批的行动。

STEP 1

数据捕获

沟通、审批、阶段变更等动作自动沉淀进客户时间线，零手工录入。

STEP 2

记忆构建

客户全景档案动态更新：阶段、互动频次、在途商机、标签画像一屏读完。

STEP 3

洞察提炼

每日简报 + 战术预警：沉默客户、临期商机、到期任务自动浮出。

STEP 4

行动执行

基于最近跟进、商机与标签生成跟进内容，进入待审批队列。

Absorbed from MARCO

编排层：多 Agent 协同 + 全程护栏

Planner 生成候选动作、Executor 产出待审工件、Verifier 回查留证——三段式执行链天然对齐 MARCO 的护栏哲学：输出要校验，失败可恢复，过程可追溯。

任务拆解输出校验错误恢复流程编排证据留档

交付层：给成果，不只给回复

数字员工的产出直接落盘为可用文件：报表、方案、清单、页面。本地设备可控、连接器可扩展，后台任务按时自动派发，人只在关键节点拍板。

文件落盘本地操控连接器扩展定时任务多角色分工
Platform Architecture · 平台架构

Palantir 式的四层平台架构

参照 Palantir Foundry 的企业级架构范式：用 Ontology 统一业务语义，用 Actions 做有门控的回写执行，用 AIP 式人机协同让 AI 提案、人拍板，治理贯穿每一层。

Layer 4 · 人机协同

AIP 协同层AI 提案 · 人拍板

跟进内容、每日简报、战术预警由引擎生成，但一律进入人工决策流——护栏内置，没有自动发送，最后一步永远在人手里。

内容生成每日简报战术预警审批门控
Layer 3 · 回写执行

Actions 执行层P-E-V 三段式执行链

Planner 提出候选动作 → Executor 产出待审工件 → Verifier 回查留证。人工批准后执行回写，动作同步沉淀进客户时间线。

Why Us · 差异优势

能力对齐之后，我们多给的四件事

三家参照对象各有边界：云端产品数据出域、开源产品交付即止。insightmarketplac 在能力对齐之外，补上的是商业交付层面的确定性。

01

闭源交付，接受定制

产品以闭源形式交付，能力按行业与场景定制：工作流、连接器、角色分工、报表口径都可以按你的业务重做一遍。

02

数据归属可控

支持本地部署形态：数据库落在你自己的机器或内网，客户资产与沟通记录不出域，不依赖第三方云端。

03

人工审批门控

自动化产物一律先进待审批队列，发送权与执行权保留在人手里。AI 负责把活干到 95%，最后 5% 由你拍板。

04

全链路审计留痕

每一次写操作、每一次 AI 执行都有审计记录，身份、时间、结果可回溯，出问题查得到，交接看得懂。
